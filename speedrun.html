PART IWhat you're actually running on
01

It's all tokens

The model never sees words, JSON, or "instructions" — just integer IDs. It predicts one token per full pass through the network, appends it, and runs again.

"Explain KV caches"→[849, 34745…]→model→next token⟲ repeat
REMEMBER

Every single output token = one full forward pass. That's the heartbeat.

02

Serving = read fast, write slow

Inference has two phases: prefill chews your whole prompt in parallel (fast), decode emits one token at a time (slow). Stable prompt prefixes get cached and skip prefill.

request→batcher→prefill ⚡→decode 🐢→stream
REMEMBER

One changed byte early in the prompt = cache gone = full price. Keep prefixes stable.

03

There is no memory, only the window

System prompt, tools, memories, RAG chunks, history, your question — everything competes for one flat token array. An assembler prioritizes, budgets, and truncates.

systemtoolsmemoryraghistory→assembler→one flat sequence
REMEMBER

Give every source a token budget — unbudgeted context fails silently.

PART IIThe agent itself
04

An agent is a while-loop

Read context → decide → call a tool → observe the result → append it → go again. That's it. Everything else in the field hangs off this cycle.

context→LLM→tool call?→execute→observe⟲
REMEMBER

The model proposes; the runtime disposes. Bound the loop or it won't stop itself.

05

Tool calls are just text

The model emits JSON. The runtime validates it, checks permissions, runs the handler, truncates the result, and feeds it back as tokens. The model never executes anything.

{"name":"search",…}→validate→policy→run→result → tokens
REMEMBER

Tool results are untrusted input — a scraped webpage can inject instructions.

06

MCP = USB for AI tools

One protocol (JSON-RPC) between your agent and any server. Every server exposes the same three things: tools, resources, prompts. M×N custom integrations become M+N.

agent host→MCP client→github · postgres · files…
REMEMBER

Treat MCP servers like npm dependencies, not config — they inject text into your loop.

07

RAG is two pipelines

Offline: chunk and embed docs into an index. Online: embed the query, fetch top matches, rerank, keep the best few. Change one lane without the other and quality silently rots.

docs→index⇢search + rerank→top-k chunks
REMEMBER

Most "hallucinations" are retrieval misses. Eval retrieval on its own.

08

Memory is a discipline, not a feature

The context window is a cache with brutal eviction. Real memory = writing important stuff to persistent stores (facts, transcripts, playbooks) and recalling it next session.

working context→ distill →stores→ recall →next session
REMEMBER

One wrong saved "fact" poisons every future session. Memories need provenance.

PART IIIWhen it grows up
09

Multi-agent = split the context, not the job title

When one window can't hold the job: an orchestrator decomposes, isolated workers run in parallel, a critic verifies before anything merges. Agents exchange messages, never memory.

orchestrator→workerworkerworker→critic→merge
REMEMBER

"Done ✓" from a worker is a claim, not a fact. Verify before you merge.

10

Gate actions by blast radius

Reads auto-run. Reversible writes get logged. Irreversible stuff (send, delete, pay, deploy) gets a human or a hard deny. Enforce it in code — the prompt is a suggestion.

proposed action→policy engine→auto/human ok?/denied
REMEMBER

Review the exact tool call (the diff, the recipient), not the conversation.

11

Agents die 5 ways

Provider errors → retry. Bad tool args → feed the error back. Confident wrong answers → independent verification. Full context → compact. Loops → circuit breaker.

timeoutbad argsconfident lieoverflowloop→5 known fixes
REMEMBER

The dangerous one is #3 — it doesn't announce itself. Never trust self-reports.

PART IVHow you know it works (the part everyone skips)
12

Evals = CI for a non-deterministic thing

Golden test cases run N times each through a sandboxed agent. Graders score the outcomes. A gate blocks regressions from shipping. Build this first, not last.

golden set→runner ×N→agent→graders→ship / block
REMEMBER

One trial is an anecdote. Grade end states, not vibes. Start with 20 real failures.

13

A model can grade a model — if you calibrate it

Give the judge a rubric with examples, control its biases (position, verbosity, self-preference), and measure its agreement with human labels. No agreement score = no judge.

transcriptrubric→judge→verdict⇢ κ vs humans
REMEMBER

An uncalibrated judge is a random-number generator with confidence.

14

Trace every step or debug blind

An agent run is a distributed trace: every LLM call and tool call is a span tagged with tokens, cost, latency, status. Metrics say something broke; the trace says what.

session▸turn▸chat $0.06execute_tool 840ms→dashboards
REMEMBER

You can't eval what you didn't record. Alert on $/task, not just errors.

15

Close the loop and you compound

Production failures → curated eval cases → safer changes → better agent → richer traces. Teams with this flywheel compound; teams without it guess.

prod→traces→eval cases→iterate→gate→prod ⟲
REMEMBER

Prompts get copied, models get upgraded — your failure corpus is the moat.
